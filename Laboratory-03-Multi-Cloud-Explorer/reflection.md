# Mission Reflection

The cloud platform that impressed me the most was **Google Cloud Platform (GCP)**, especially because of its strong focus on artificial intelligence, machine learning, and cloud-native technologies. Services such as Vertex AI make it possible to build, train, and deploy machine learning models, while Google Kubernetes Engine provides a managed environment for containerized applications. I also found it interesting that Kubernetes originated from technology developed at Google before becoming an open-source project.

AWS, Microsoft Azure, and GCP have many similarities. All three provide virtual machines, object storage, networking, identity and access management, managed databases, Kubernetes services, monitoring tools, and global cloud infrastructure. Although their service names are different, they solve many of the same computing problems.

This activity helped me understand that business requirements should guide the choice of cloud platform. A company must consider its existing technologies, budget, expected growth, availability requirements, technical skills, security needs, and workload type. For example, Azure can be a practical choice for an organization already using Microsoft technologies, while GCP can be attractive for AI and Kubernetes workloads.

By acting as a Cloud Solutions Consultant, I learned that there is no single cloud provider that is automatically best for every organization. A good recommendation should connect technical services to a client's actual goals and constraints rather than simply choosing the most popular provider.

My GitHub Cloud Computing Portfolio also became more organized and professional after this mission. I added separate research documents, comparison tables, recommendation matrices, screenshots, Linux investigation results, and references. I also practiced using meaningful Git commits after each checkpoint, which makes the repository history easier to understand and provides evidence of how the activity was completed.
